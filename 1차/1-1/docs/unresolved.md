  - 3회차: AI Native 공고로 바뀌었으나, 출처가 【turn…】 내부 표기로 남아 공고를 확인할 수 없고, 프로보티브(3년 이상)처럼 경력 조건이 경계에 걸린 공고가 포함됨
- **재시도 후에도 해결되지 않은 부분**
  - 원문에서 확인되는 사실: 정상적인 결과를 얻기까지 재요청이 2번 필요했음
  - 3회차 응답에서 원문으로 확인되는 표기 상태 (AI 관찰): 출처 표기가 「【turn272142search4】」 같은 내부 표기 그대로 남아 있음. 3회차 AI 응답 원문 그대로임
  - 3회차 결과에 대한 판단: 충족하지 못함 (위 두 문제)

**⑥ 미해결 원인**

| 검토 항목 | 원문 근거 | 판단 |
|---|---|---|

**⑦ 막힌 이유 (직접 작성)**

처음 요청에 'AI Native'와 '3년차 경력'이라는 조건을 쓰지 않았더니, AI는 내 이력의 대부분인 모바일 앱 개발 공고를 가져왔고 5년 이상 공고도 섞었다.

두 번째 요청에서 "앱개발을 주된 영역으로 수집함"이라고 틀린 점만 적고 원하는 결과를 직접 쓰지 않았더니, AI는 오히려 AI Native 공고를 빼 버렸다. 지적만 하고 원하는 것을 긍정형으로 말하지 않은 것이 반대 해석의 원인이었다고 본다.

세 번째에야 AI Native 공고 5개를 받았지만 두 가지가 끝내 해결되지 않았다.
- 출처가 【turn272142search4】 같은 내부 표기로 나와, 공고를 직접 열어 실제로 있는지 확인할 수 없었다.
- 경력 기준이 정리되지 않았다. AI는 인턴을 빼고 내 경력을 약 2년 2개월로 계산했고, 나는 "3년차"라고 말했고, 공고는 "3년 이상"을 요구했다. 세 기준이 서로 달라서 프로보티브(3년 이상)처럼 경계에 걸린 공고가 적합한지 판단할 수 없었다.

공고를 확인할 수 없고 경력 기준도 맞추지 못해 미해결로 남긴다.

현재 경력기술서에서는 기존 iOS·Flutter 개발 경험에 비해 AI 활용 경험이 충분히 드러나지 않습니다.

다음과 같이 AI 관련 프로젝트를 별도 항목으로 구성하는 방향이 적절합니다.

프로젝트: AI 기반 취업 준비 에이전트 설계

확인된 경험 기반 초안

- 취업 준비 과정을 지원하는 AI Agent의 역할과 수행 범위 설계
- System Prompt와 User Prompt를 분리해 에이전트의 역할 및 사용자 입력 구조 정의
- Zero-shot 및 Few-shot 방식으로 프롬프트를 구성하고 여러 AI 모델의 응답 결과 비교
- AI 응답의 정확성과 일관성을 확인하기 위한 검증 질문 설계
- AI Agent 수행, AI 협업 학습, 직접 수행 학습으로 과업을 분류하는 기준 설계
- AI 결과물의 오류와 누락을 확인하고 프롬프트 개선 방향 도출

이 내용은 현재 대화에서 확인된 활동을 기반으로 작성한 것이며, 실제 서비스 개발이나 자동화 구현을 완료했다는 의미는 아닙니다.

5. 최종 분석

현재 확인된 AI Native 역량은 다음과 같이 정리할 수 있습니다.

| 역량 | 현재 확인 수준 |
|---|---|
| AI 도구 활용 및 협업 | 경험 있음 |
| Prompt Engineering | 경험 있음 |
| AI 모델 결과 비교 및 검증 | 경험 있음 |
| AI Agent 설계 | 설계 경험 있음 |
| LLM API 활용 | 프로젝트 경험 있음 |
| Agent 실제 구현 | 확인 필요 |
| Tool Calling / RAG | 확인된 경험 없음 |
| AI 기반 개발 자동화 | 설계 경험 있음, 구현 범위 확인 필요 |

경력기술서 수정 방향

기존 모바일 개발 경력을 삭제하거나 AI 개발 경력처럼 바꾸는 것이 아니라, 모바일 개발 경험을 기반으로 AI를 어떻게 활용했는지 별도로 보여주는 것이 좋습니다.

특히 다음 세 가지를 강조해야 합니다.

1. AI를 단순히 검색이나 코드 생성에 사용하는 수준을 넘어 업무 수행 방식에 적용한 경험
2. 프롬프트를 설계하고 모델의 결과를 비교·검증한 경험
3. LLM을 실제 프로젝트 기능에 활용한 경험

단, AI 활용 경험을 경력기술서에 기재할 때는 업무에서 사용한 경험, 개인 프로젝트에서 사용한 경험, 학습 과정에서 수행한 경험을 구분해야 합니다. 그래야 실제 경력과 AI Native 역량을 모두 정확하게 보여줄 수 있습니다.

**[AI 응답 원문 끝 — 2회차]**

**⑤ 최종 결과**

- **사용자가 원했던 결과** (2회차 User 프롬프트 기준)
  - AI Native 지원이라는 목적에 맞게 AI 활용 능력 관련 경력에 초점을 맞춘 경력기술서·채용공고 대조와 수정안
- **AI가 실제로 제공한 결과**
  - 1회차: 과제 1의 1회차 공고(뉴날·Joint·티맵모빌리티·골든플래닛·더씨에스알)를 기준으로 Swift·Flutter·Python·FastAPI 등 기술 스택 일치 여부를 중심으로 대조하고, H2O·Welgram·VoltMicro·Simple Closet 경력 문구 수정안을 제시함
  - 2회차: 비교 기준을 AI 활용 경험 7개 항목으로 바꾸고, 과제 1의 3회차 AI Native 공고 5개를 기준으로 대조함. 경력기술서 수정안으로 "AI 기반 취업 준비 에이전트 설계" 프로젝트 초안을 따로 제시함
- **두 결과의 차이**
  - 1회차: AI 활용 경력에 초점을 맞추지 않음. 1회차 AI 응답 원문에 따르면 이미 사용자가 다시 요청한 과제 1의 1회차 공고 5개를 대조 기준으로 다시 사용함 (2회차 User 프롬프트에서 사용자가 지적)
  - 2회차: AI 활용 경험 중심으로 바뀌었으나 근거가 미션 활동(프롬프트 설계·모델 비교)에 한정되고, 실제 출시 앱의 AI API 활용(패킹즈 Gemini, 이집사 OpenAI)은 반영되지 않음
- **재시도 후에도 해결되지 않은 부분**
  - 원문에서 확인되는 사실: 2회차 수정안은 별도 AI 프로젝트 항목 초안 하나이며, 응답 원문에 "실제 서비스 개발이나 자동화 구현을 완료했다는 의미는 아닙니다"라고 적혀 있음
  - 원문에서 확인되는 사실: 2회차 대조표에서 "Tool Calling", "RAG", "AI 기반 코드 생성·디버깅"은 "근거 부족"으로 남음
  - 2회차 결과에 대한 판단: 일부만 충족

**⑥ 미해결 원인**

| 검토 항목 | 원문 근거 | 판단 |
|---|---|---|
| 사용자 요구사항 이해 부족 | 최초 User 프롬프트에는 "AI Native" 초점이 적혀 있지 않음. 2회차 AI 응답은 "기존 비교에서는 Swift, Flutter, Python, FastAPI 등 기술 스택의 일치 여부에 집중했습니다"라고 1회차의 기준 차이를 인정함 | 원문으로 확인됨 |

**⑦ 막힌 이유 (직접 작성)**

처음 요청에 'AI Native 지원'이라는 목적과 '과제 1의 3회차 공고를 기준으로'라는 조건을 쓰지 않았더니, AI는 내가 이미 다시 요청했던 1회차 공고로 기술 스택만 비교했다. 앞 과제에서 바로잡은 결과가 다음 과제로 이어지지 않았다.

재요청 후 AI 활용 경험 중심으로 바뀌었지만, 근거로 찾은 경험은 이번 미션에서 한 프롬프트 설계와 모델 비교뿐이었고 수정안도 '취업 준비 에이전트 설계' 초안 하나였다. 실제로 출시한 앱에서 AI API를 쓴 경험(패킹즈의 Gemini API, 이집사의 OpenAI API)은 대조표에 나오지 않았고, 대신 Stidi의 OpenAI 활용만 반복해서 언급했다. 내 이력서에 AI 활용 경험이 프로젝트마다 흩어져 있어서 AI가 찾아내지 못한 것 같다.

Tool Calling·RAG가 '근거 부족'으로 남은 것은 AI가 정확하게 표시한 것이 맞다. 다만 내 경력 안에서 AI Native 공고에 대응할 경험이 부족하다는 점은 프롬프트로 해결할 수 없는 문제라서 미해결로 남긴다.

## 4. 종합 분석

### 4-1. 반복적으로 나타난 문제 유형

**[원문 근거]**
- 두 과제 모두 최초 요청에는 "AI Native"라는 조건이 적혀 있지 않았고, 사용자가 재요청에서 이 조건을 밝힌 뒤에야 AI가 기준을 바꿨습니다.
- 과제 1 2회차에서 AI는 사용자의 지적("ai native 특화된 공고보다는 앱개발을 주된 영역으로 수집함")을 반대로 해석했습니다. 3회차 AI 응답에서도 "앞선 비교에서 요구사항을 반대로 이해했습니다"라고 인정했습니다.
- 과제 2 1회차는 과제 1의 최종(3회차) 공고가 아니라 1회차 공고를 대조 기준으로 다시 썼습니다.

**[AI 분석·추론]**
- 반복된 패턴은 두 가지로 보입니다. 하나는 사용자의 최종 목표(AI Native 직무 지원)가 매 요청에 들어 있지 않으면 AI가 일반 모바일 개발 기준으로 되돌아가는 것이고, 다른 하나는 앞 과제에서 바로잡은 결과가 다음 과제의 기준으로 이어지지 않는 것입니다.
- 비판형 피드백(예: "A보다는 B를 주로 수집함")을 지시로 바꾸는 과정에서 방향을 거꾸로 해석한 사례가 있었습니다.

### 4-2. System Prompt 수정으로도 해결되지 않은 문제

**[원문 근거]**
- 원문에는 System Prompt를 수정하거나 변경한 기록이 없습니다. 확인되는 해결 시도는 모두 User 프롬프트를 통한 재요청입니다.

**[AI 분석·추론]**
- 두 과제는 System Prompt v1 상태에서 User 프롬프트 재요청으로 해결을 시도했습니다. 막힌 지점은 이후 System Prompt v2의 4-4·4-5 항목(채용공고 검색 기준, 경력기술서 수정 기준)에 반영했습니다(system-design.md 13장 9·10번).

### 4-3. 현재 프롬프트의 한계

**[원문 근거]**
- 과제 1 최초 User 프롬프트에는 직무 유형(AI Native), 경력 범위(3년차), 제외 조건(상향 지원 제외)이 없습니다.
- 과제 2 최초 User 프롬프트에는 대조 기준 공고(과제 1의 어느 결과인지)와 초점(AI 활용 경력)이 없습니다.
- 과제 1 2회차 User 프롬프트는 문제점을 지적하지만, 원하는 결과를 직접 말하지는 않습니다("다시 비교해주세요").

**[AI 분석·추론]**
- 핵심 조건이 대화 맥락이나 사용자 머릿속에만 있고 프롬프트에 적혀 있지 않아, AI가 기본값(일반 모바일 개발, 이전 공고 목록)으로 채운 것으로 보입니다.
- 지적형 재요청은 해석 여지가 있어, 이번처럼 반대 방향으로 해석될 수 있습니다.

### 4-4. 추가로 개선해야 할 사항

**[AI 분석·추론 — 제안이며 원문에 있는 내용이 아님]**
- 최초 요청에 목표 직무(AI Native), 경력 범위(예: 경력 요건 3년 이하 또는 "3년 내외"), 제외 조건(4년 이상 필수 공고 제외)을 직접 적기
- 재요청은 "무엇이 틀렸는지"와 함께 "무엇을 원하는지"를 긍정형으로 적기 (예: "AI Native 특화 공고만 5개 수집")
- 과제 2처럼 앞 과제 결과를 이어받을 때는 기준 자료를 직접 지정하기 (예: "3회차에서 수집한 AI Native 공고 5개 기준")
- 이 조건들을 반복해서 써야 한다면 System Prompt에 고정 조건으로 넣고, 그 변경 내용을 과제 기록에 남기기
- 출처 표기가 실제 링크로 나오는지 확인하는 검증 단계 추가
